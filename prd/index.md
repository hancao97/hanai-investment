# Hanai Investment 产品需求文档

> 版本：v0.2
> 更新日期：2026-08-02
> 产品定位：本地优先的 A 股行情、估值与单专家投资研判桌面工作台

## 1. 核心目标

用户从股票详情或“大师研判”入口选择一只股票和一位专家。系统创建独立工作目录，同步该专家 Skill，启动一个不可人工插话的一次性 Codex Agent 任务。Agent 主动获取最新公开资料、完成详细投资分析，并将唯一正式成果写入根目录 `REPORT.md`。

任务执行期间展示可审计的实时过程；报告通过完整性校验后，任务转为只读归档。用户只能查看过程和报告，不能继续对话或追加指令。

## 2. 信息架构

| 一级导航 | 主要内容 | 主要动作 |
|---|---|---|
| 今日市场 | 指数、市场宽度、成交额、板块热力、榜单 | 刷新、板块下钻、打开股票 |
| 自选与发现 | 自选分组、全市场搜索、行情列表 | 搜索、添加、移除、分组 |
| 大师研判 | 研判归档列表、股票/分析人筛选 | 新建任务、查看执行过程与报告 |
| 专家中心 | 已安装的专家 Skill | 查看专家框架 |
| 设置与诊断 | Codex、模型、数据源、存储 | 重启检测、选择模型、清缓存 |

旧会话式研究、多角色讨论及主持席位不属于新产品范围。

## 3. 大师研判流程

1. 用户选择股票和且仅一位专家。
2. 系统确认 Codex 已就绪，并创建唯一任务 ID。
3. 系统创建 `runtime/workdir/judgements/<task-id>/`。
4. 将所选专家 Skill 同步至 `agents/skills/<persona-id>/`，不复制原始二进制来源或生产脚本。
5. 写入 `AGENTS.md` 和 `RUN.json`，启动独立 Codex thread。
6. 向 Agent 提供且仅提供股票名、代码、专家身份和工作要求；不提供旧证据快照。
7. Agent 自行联网检索公司公告、财报、监管披露、行业资料和其他必要来源。
8. UI 实时展示搜索、命令、推理摘要、工具调用与文件变更，持久化至 `activity.jsonl`。
9. Agent 将完整成果写入 `REPORT.md`；系统检查文件存在且达到最低完整性要求。
10. 若报告缺失或过短，系统自动发出一次补全指令，不需要也不允许用户插入。
11. 校验成功后记录完成时间和 SHA-256，并归档 Codex thread。
12. 任务永久转为只读报告视图；失败任务保留过程与目录，但不能续聊，只能新建另一项任务。

## 4. 工作目录规范

```text
judgements/<task-id>/
├── AGENTS.md                         # 当前任务的执行边界
├── RUN.json                          # 股票、分析人、模型、状态和时间
├── activity.jsonl                    # 可审计执行轨迹
├── REPORT.md                         # 唯一正式成果
└── agents/skills/<persona-id>/       # 本次任务同步的专家能力
    ├── SKILL.md
    └── references/...
```

`REPORT.md` 至少应包含：执行摘要、信息时点与来源、业务与竞争格局、财务质量、估值与假设、催化剂、核心风险、情景分析、待验证清单和符合专家框架的最终研判。

## 5. 交互要求

- 新建弹窗明确展示“单专家、一次性执行、完成后只读”。
- 分析专家使用单选交互，不出现主持人、委员会或多选。
- 列表至少展示股票名/代码、分析人、分析日期、模型和状态。
- 列表支持股票名或代码模糊筛选，以及分析人筛选。
- 执行页展示四阶段进度：创建工作区、主动检索与分析、报告校验、只读归档。
- 执行中没有输入框、发送按钮、停止后续聊或中途追加材料能力。
- 报告完成后展示全文、文件大小、SHA-256、分析人和时间，可打开归档目录。
- 失败任务解释原因并允许“重新创建研判”，新任务必须获得新的任务 ID 和目录。

## 6. 数据模型

`JudgementRun` 必须包含：

- `id`, `secId`, `code`, `stockName`
- `personaId`, `personaName`
- `status`: `preparing | running | verifying | completed | failed`
- `directory`, `reportPath`, `skillPath`
- `codexThreadId`, `model`
- `createdAt`, `updatedAt`, `completedAt`, `error`

SQLite 仅持久化任务元数据；报告和执行轨迹以文件为准。

## 7. Codex 模型发现与诊断

- 模型列表必须来自 app-server `model/list`，不能硬编码 GPT 版本。
- 默认只显示当前账号正常可用的非隐藏模型。
- 用户选择的模型持久化到本地设置，后续任务记录实际使用模型。
- 若 app-server 无法解析最新模型目录，设置页应显示明确升级提示与命令。
- 升级 Codex 后重新检测，GPT-5.6 等新模型应自动出现在下拉框中。

## 8. 异常与恢复

- Codex 不可用时禁止创建任务，但行情、自选和详情继续可用。
- 应用在报告完成前退出时，重启后将该任务标为失败并保留目录，不伪装为仍在运行。
- 报告完成与线程归档解耦：若线程归档失败，已落盘报告仍视为有效本地归档。
- 所有写入限制在当前任务工作目录，越界写入继续走 Codex 审批。

## 9. 非目标

- 持续聊天、追问、消息历史和会话恢复
- 多专家委员会、互评、主持终审或中立角色
- 人工中途插话、追加证据或修改 Agent 任务
- 冻结证据包、旧讨论轮次与旧报告格式兼容
- 券商接入、自动交易、收益承诺或确定性买卖指令
